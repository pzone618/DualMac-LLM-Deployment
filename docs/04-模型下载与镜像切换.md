# 04｜模型下载、断点续传与 hf-mirror.com 切换（v1.1）

> **两台 Mac 通用**。M4 主控可通过 SSH 一次操作两台 Mac。所有命令从 `~/AI/dual-mac-cluster` 执行。
>
> **下载器**：`huggingface_hub` 获取 Repo/commit/文件元数据；`aria2c` 下载公开 GGUF；完整性验签可使用 HF LFS 上游 SHA256。不能保证所有 CDN/镜像都支持 HTTP Range，也不能保证受限模型可以从镜像下载。

## 1. 下载源与策略

| 下载模式 | 实际端点 | 用途 | 鉴权 |
|---|---|---|---|
| `official` | `https://huggingface.co` | 海外网络稳定、授权模型 | 官方 HF 才允许 Token |
| `mirror` | `https://hf-mirror.com` | 官方站很慢或不可达 | **不向镜像发 Token**，仅公开模型 |
| `auto` | 官方站先试，失败后镜像 | 推荐默认；兼顾不同网络环境 | 不向镜像发 Token |

配置文件（M4 和 M6 都有）：

```bash
cd ~/AI/dual-mac-cluster
nano config/cluster.env
# 确保包含：
HF_SOURCE=auto
```

单次下载可用 CLI `--source` 覆盖默认配置，**不需要重启 llama.cpp**。

镜像服务是第三方运营的公共服务，而非 Hugging Face 官方基础设施。它的可用性、缓存同步和服务政策可能变化；只在你信任的网络路径下使用，敏感模型和凭证始终走官方站。

## 2. 三种基本下载命令

### A. 官方站

```bash
./scripts/download-model.sh ggml-org/gemma-3-1b-it-GGUF \
  --file gemma-3-1b-it-Q4_K_M.gguf --source official
```

### B. 镜像站 hf-mirror.com

```bash
./scripts/download-model.sh ggml-org/gemma-3-1b-it-GGUF \
  --file gemma-3-1b-it-Q4_K_M.gguf --source mirror
```

### C. 自动故障切换（推荐）

```bash
./scripts/download-model.sh ggml-org/gemma-3-1b-it-GGUF \
  --file gemma-3-1b-it-Q4_K_M.gguf --source auto
```

上述三种均写入**相同的模型目录**。如果官方站下载到 40% 中断，可在保留 `.aria2` 状态文件和 `.source.json` 的前提下改用 `--source mirror`，继续尝试恢复。下载前脚本解析仓库的不可变 **commit SHA**；只有元数据里的 commit/文件大小/上游 SHA 一致才允许复用已有文件，否则拒绝合并。

> 断点续传依赖下载服务器/重定向目标的 HTTP Range 支持。如果服务器返回无 Range 能力、链接过期或者同一份模型在镜像未同步，下载可能失败，**不会保证从百分比位置恢复**。可以重跑命令、切换到官方源；若 checksum 不符，必须人工隔离下载文件，不能绕过验证强行运行。

## 3. 在 M4 Pro 上统一管理两台机器

M4 上运行：

```bash
cd ~/AI/dual-mac-cluster

# 让两个节点都各自下载同一模型（相同 revision）
./scripts/model-manager.sh download both ggml-org/gemma-3-1b-it-GGUF \
  --file gemma-3-1b-it-Q4_K_M.gguf --source mirror

# 只在 M4 下载：
./scripts/model-manager.sh download m4 ggml-org/gemma-3-1b-it-GGUF \
  --file gemma-3-1b-it-Q4_K_M.gguf --source auto

# 只在 M6 下载：
./scripts/model-manager.sh download m6 ggml-org/gemma-3-1b-it-GGUF \
  --file gemma-3-1b-it-Q4_K_M.gguf --source auto

# 检查两台 GGUF 文件清单：
./scripts/model-manager.sh inventory
```

**降低重复外网下载**：让 M4 先下载完成并校验，再通过 Thunderbolt + SSH 的 rsync 续传复制到 M6：

```bash
./scripts/model-manager.sh sync ggml-org/gemma-3-1b-it-GGUF \
  gemma-3-1b-it-Q4_K_M.gguf
```

`sync` 会对 M4 和 M6 的文件各做一次 SHA256 验证；如果已有同名旧模型，不应未经核对版本直接覆盖。同步命令只支持仓库根目录的单文件 GGUF；多层文件和分片可通过独立的 `download both --pattern` 下载。

## 4. 下载终止后如何恢复

1. **不要删除** `.aria2` 或 `.source.json`，也不要用 Finder 改名临时文件。
2. 重新执行**相同 repo、相同文件和 revision**的下载命令。如果之前用的是 `--revision main`，建议从首次日志取出已解析的 40 位 commit，使用 `--revision <原SHA>` 锁定版本。
3. 如需切镜像，只修改 `--source mirror` 或 `--source official`，保持文件名和 commit 不变。
4. 如果出现 `Model changed since partial download`，意味着仓库 revision/文件大小/上游 checksum 发生变化。将旧模型及关联状态移入备份文件夹，**不要将两版本文件片段拼接**。
5. 如果出现 `Range`、`416`、`aria2` 或重定向失败，先使用相同命令重试，再检查目标地址，切换端点；无法续传时应保留备份后重新下载。

aria2 控制文件示例：

```text
~/AI/models/ggml-org__gemma-3-1b-it-GGUF/
├── gemma-3-1b-it-Q4_K_M.gguf
├── gemma-3-1b-it-Q4_K_M.gguf.aria2       # 进行中可能存在
└── .gemma-3-1b-it-Q4_K_M.gguf.source.json  # 版本/校验元数据
```

中断期间 `.aria2` 存在是正常现象；完成后 aria2 通常删除控制文件。

## 5. 下载文件校验及可信度

```bash
./scripts/download-model.sh verify ggml-org/gemma-3-1b-it-GGUF \
  gemma-3-1b-it-Q4_K_M.gguf

./scripts/model-manager.sh verify both ggml-org/gemma-3-1b-it-GGUF \
  gemma-3-1b-it-Q4_K_M.gguf
```

校验等级：

- `upstream_sha256`：通过 Hugging Face 仓库元数据获得的 SHA256 与本地文件一致；推荐。
- `size+local_sha256_only`：上游未提供 LFS SHA，只验证大小并记录本地 hash；**不能证明官方内容来源**。
- `local_sha256_only`：只记录本地 hash，证明后续传输/使用时文件没有发生变化，并不证明上游来源。

如果页面或可信发布渠道给出了 SHA256，可以手动传入：

```bash
./scripts/download-model.sh ggml-org/gemma-3-1b-it-GGUF \
  --file gemma-3-1b-it-Q4_K_M.gguf --source official \
  --sha256 8ccc5cd1f1b3602548715ae25a66ed73fd5dc68a210412eea643eb20eb75a135
```

该 SHA256 是撰写手册时 Hugging Face 页面显示的示例校验值；实际操作前需与仓库当前选定 commit 的文件校验信息核对，**不能用于不同文件或不同版本**。

## 6. 分片 GGUF（27B/32B/70B 常见）

先到仓库 Files 页面确认模型分片命名，再用明确量化过滤模式：

```bash
# 将 OWNER/REPO 换成真实的仓库路径
./scripts/model-manager.sh download m4 OWNER/REPO \
  --pattern '*Q4_K_M*.gguf' --source auto
```

下载器会检查形如 `model-Q4_K_M-00001-of-00005.gguf` 的全部分片是否在选择结果中；遇到不完整分片会拒绝继续。将 `config/cluster.env` 中 `DISTRIBUTED_MODEL_FILE` 设置为**第一片的完整文件名**。若文件位于仓库子目录中，路径要相对于 Repo 根目录。

不要盲目对整个 Repo 执行 `hf download`，否则可能一次下载多种量化格式，浪费几十乃至几百 GB 磁盘空间。

## 7. 私有模型 / gated 模型

建议仅在确有需要下载的节点、官方 Hugging Face 页面完成授权，并使用官方 CLI 登录：

```bash
~/AI/.venv/bin/hf auth login
./scripts/download-model.sh OWNER/PRIVATE_REPO \
  --file model.gguf --source official --engine hf
```

**不会把你的 HF Token 发送到 hf-mirror.com**。官方 HF 下载器使用原生缓存系统，在某些版本或 Xet 存储模式下，中断续传的行为可能不同于 aria2，**不要把它当成统一的 HTTP Range 续传保证**。不要将 token 写入 `cluster.env`、Git 仓库或任何脚本。

## 8. Hugging Face CLI 直接使用镜像（备选）

如果仅需快速使用官方工具，不使用本包的 SHA/续传控制，也可在当前 shell 指定：

```bash
HF_ENDPOINT=https://hf-mirror.com \
  ~/AI/.venv/bin/hf download ggml-org/gemma-3-1b-it-GGUF \
  --include '*Q4_K_M*.gguf' \
  --local-dir ~/AI/manual-models/gemma-3-1b
```

这个路径是**另一个模型目录**，不会自动成为集群脚本的模型路径。要纳入集群，优先使用本包下载器，或在核对 SHA 后手工调整路径和配置。

官方镜像主页给出了 `HF_ENDPOINT=https://hf-mirror.com` 的用法，也提供自己的 `hfd` 工具；本包不自动执行第三方 `hfd.sh`，因为本包已使用 Homebrew 的 aria2 和受控 Python 下载器。

## 9. 故障排查

| 现象 | 建议 |
|---|---|
| 官方站超时 | 改 `--source mirror`，或默认 `auto` |
| 镜像 404 / 版本落后 | 改 `--source official`，检查 pinned SHA 是否已同步 |
| 无法续传 | 服务器不支持 Range/下载状态不同，先备份，再清理重下载 |
| `SHA256 mismatch` | **停止使用**该文件，隔离并从可信来源重新获取 |
| `.aria2` 持续存在 | 下载仍未完整成功或控制文件未被正确移除，查 aria2 输出 |
| `401/403` / gated | 登录官方、申请许可并采用 `--source official --engine hf` |
| 只有官方可以访问、镜像不可达 | 设 `HF_SOURCE=official` |
| M4 成功，M6 失败 | 改用 `model-manager.sh sync` 走 Thunderbolt，或查 M6 DNS/代理 |
| 磁盘耗尽 | `df -h ~/AI`、避免同时下载多个量化版本 |
