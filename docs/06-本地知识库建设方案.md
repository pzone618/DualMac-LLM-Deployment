# 用两台 Mac mini 建设可回查原文的本地知识库

**现有模型足够启动第一版。** 建议先用 OCRmyPDF/Tesseract 识别扫描文字，用 Qwen3-VL-8B 复核疑难区域，用 Qwen3-Embedding-0.6B 建立文本索引，再用 Gemma 4 31B Q4_0 根据检索到的原文回答。第一笔投入应放在挑选代表性样本、标注正确页码和检查数字上。若原页的金额被识别错，即使问答模型准确引用了这一段，答案仍然会错。

以下按本地处理、以文字提问并返回原文或图片出处设计。两台 Mac 各有 24 GB 统一内存。已有实测覆盖 12 个主模型的启停、文本请求或向量请求。图像识别、OCR 准确率、整库检索质量和每小时处理页数，均需用你的资料测量。[双机实测及完整配置](05-双机模型启停实测.md)

## 二、按页选择解析方法

| 输入与判断依据 | 建议处理顺序 | 需要保存的证据 |
|---|---|---|
| 有可用文本层的 PDF | 用 Poppler 的 pdftotext 按页提取；抽查双栏顺序、中文乱码、页眉页脚和脚注。只重做存在问题的页或区域。 | 原文件、物理页序、印刷页码、文本块与坐标 |
| 扫描、歪斜或混合 PDF | 逐页检查文本覆盖和可读性。有些页已有错误 OCR 层；将这些页重做 OCR。旋转纠正后再按语言识别，低清小字从原页重新裁取。 | 原页图、处理图、OCR 原文和文字框；保留识别失败页 |
| 多栏、表格和公式 | 先区分栏、表头、单元格、脚注；把整表图和单元格裁图同时保留。让视觉模型按行列转录，核对合并单元格、负号、小数点、单位。公式保留原图供回读。 | 表标题、行列键、原值及单位、页码和裁图坐标 |
| 可重排 EPUB | 从容器定位 OPF，按 spine 的阅读顺序遍历 XHTML。保留章标题、段落、脚注链接、图片说明和资源路径。固定版式或正文只有图片的章节转入图片流程。 | 书名、章节路径、XHTML href、元素 ID；没有 ID 时保存本版本内稳定的段落序号 |
| 截图、照片、示意图 | 文字截图先 OCR；照片和示意图生成可检索的描述。流程图记录箭头方向，图表记录标题、坐标轴和单位。模糊处保存“不可辨认”。 | 原图、局部裁图、可见文字、图像描述分别存储 |

例如中英混排的纯扫描件，在安装对应语言包后，可以对副本尝试以下命令。繁体中文选用相应的 `chi_tra` 语言包。混合 PDF 应单独检查原有文字层。OCRmyPDF 的 sidecar 只含本次 OCR 生成的文字，因此整本文本应从输出 PDF 逐页提取。[OCRmyPDF 官方操作手册](https://ocrmypdf.readthedocs.io/en/latest/cookbook.html) · [EPUB 3.3 出版物结构](https://www.w3.org/TR/epub-33/)

```bash
ocrmypdf --rotate-pages --deskew -l chi_sim+eng scan.pdf scan.searchable.pdf
pdftotext -bbox-layout scan.searchable.pdf scan.words.html
```

疑难区域的视觉提示可从这句开始：“逐行转录可见文字，保留单位、标点和空白单元格。看不清的位置写〔不可辨〕。将图像描述单独输出。” 如果 OCR 得到“0.8”、视觉模型得到“0.6”，保留两种结果并把原图送审。低分辨率原件中已经丢失的细节，优先找更好的扫描源。

## 三、从一页原文到一条有出处的回答

1. **登记来源。** 原文件只读，用文件内容哈希作版本标识。PDF 同时保存物理页序和印刷页码；EPUB 保存章节锚点；独立图片保存文件和裁图位置。保留解析器版本及用于裁切的坐标系，方便在原件上准确高亮。
2. **生成可回查的块。** 以标题、段落或表格为边界，试用每块 300–500 tokens、连续正文重叠约 50 tokens。每块附章节路径。跨页续表保留同一表 ID，分块时重复列标题与单位；OCR 原文、人工更正、模型描述放在不同字段。
3. **建立两条检索路径。** 小语料先用 SQLite 保存块、引用和关键词索引，向量可用归一化后精确点积做基线，积累规模和延迟数据后再选向量数据库。中文关键词索引先做分词或字符 n-gram，另给编号、版本号、型号保留精确匹配字段。文档向量用原文；查询按 Qwen 模型卡添加检索任务指令。记录模型版本、向量维数、归一化和查询模板，更换向量模型后重建对应索引。[Qwen3-Embedding 模型卡](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B)
4. **融合、去重、回答。** 可从关键词和向量各取前 10 块，按名次融合，折叠同页近重复段落，择 3–5 块送给问答模型。4096 上下文还要容纳指令、问题和输出，按实际 token 数裁切。要求答案逐项给出块 ID；引用链接由程序从块 ID 生成，并检查该 ID 确实在本次检索结果内。证据不足就列出缺失信息。
5. **支持增量重跑。** 按“文件版本＋页或章节＋解析配置”记录完成状态，识别失败的页可单独重试。修正页文后，只重算受影响的块；新版本索引写完再切换，同时撤下旧块。这样搜到旧数字时能追溯是哪一版原件或哪轮 OCR 产生的。

例如用户问“表 3 的设备 B 最大电流是多少”，关键词通道负责找到“设备 B”和“表 3”，向量通道补充“额定上限”等近义表达。答案应同时引用行名、数值和单位，并能打开相应页的表格裁图。若只找到了设备名称，不能据邻行数据作答。

## 四、在两台 24 GB Mac 上怎样排班

| 时段 | M4 Pro | M6 | 验证重点 |
|---|---|---|---|
| 批量入库 | 挂载模型盘和资料盘，提取原生文本、拆分 EPUB、运行 OCR，先以单任务测资源。 | 可空闲；如安排独立 OCR 作业，按文档分批，处理结果汇总到 M4。 | 页/小时、失败页、磁盘临时空间、重跑是否重复入库 |
| 疑难页复核 | 先试单机启动 8B 视觉模型及对应投影器，每次送一张裁图；记录输入像素、耗时和内存。 | 单机资源不足时，按现有 RPC 流程参与一次双机对照。 | 真实图片响应、细字与表格错误率；图像输入会占用上下文 |
| 建立向量索引 | 关闭视觉服务，使用 `--embedding` 启动 0.6B 模型，批量请求 `/v1/embeddings`。 | 首轮可用已验证的双机配置，之后比较单机的块/秒。 | 每块有向量、维数固定，断点后从未完成块继续 |
| 日常问答 | 关键词和查询向量检索在此完成，再由主节点启动 Gemma Q4_0 提供答案。 | 先启动 RPC worker，接收主节点分配的模型计算。 | 同时记录检索耗时、模型是否已加载、首 token 和整题延迟 |

**在线问答仍需给新问题生成查询向量。** 第一版可以先批量编码评测问题，再切换到双机问答模型。正式交互时，优先试验独立的本地 CPU 嵌入服务（单独端口，禁用 GPU 层卸载），同时让大模型使用双机 RPC；测过双服务内存和延迟后再常驻。若资源吃紧，先保留关键词即时检索，再按批次运行向量检索和问答。工程原有 master 启动脚本管理一个分布式文本模型；部署第二个端点需独立配置进程和端口。[工程启动方式](../README.md)

视觉试验需要在主模型参数上显式添加同目录投影器 `--mmproj <完整路径>`，向 `/v1/chat/completions` 发送一张带已知内容的裁图，消息中包含文字和 `image_url`（可用本地图片的 base64 data URL）。先核对图上的唯一编号和一处小数，再记录准确率。文本嵌入端点返回向量。两种接口已用 context705 核对，当前工程的实机图像准确率仍待测。[llama.cpp server 文档](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md)

## 五、先用代表性样本决定是否扩容

建议第一批选 10 页清晰 PDF、10 页模糊或歪斜扫描、10 页表格或双栏、2 个 EPUB 章节和 10 张图片。人工标出关键文字、数字、表格归属和出处，准备 20 道有答案的问题及 5 道资料中缺少答案的问题。保留一部分样本到最后验收，避免参数只适合调试页。以下是建议起点，正式门槛由资料用途决定。

| 检查项 | 如何判定 | 失败后先改什么 |
|---|---|---|
| 文字与数字 | 用人工转录计算字符错误率，分别报告清晰页和困难页。金额、日期、单位、负号单独核对；未确认的关键字段标记待审。 | 核查原图、语言包、裁切和分辨率。表格错行优先换版面提取方法。 |
| 能否找到出处 | 20 道有答案的问题中，先以至少 18 道的正确来源进入前 5 块为试运行目标。编号查询和语义查询分别统计。 | 正确页未入库先修解析；已入库则查切块、分词及查询指令。正确页常在前 20 却进不了前 5，再试重排器。 |
| 回答是否有据 | 打开每个引用，核实它支持整条结论。记录正确答案数、引用支持率，以及 5 个缺证据问题中模型编答了几个。 | 对照检索上下文。缺行补邻块；证据齐仍答错，再比较 Gemma 与 GPT-OSS。 |
| 是否能跑完整批 | 分开记录 OCR 页/小时、需视觉复核页占比、向量块/秒，以及冷启动和热服务问答耗时。中断一次后重启，核对页数和块数。 | 针对耗时占比最大的阶段优化，估算全库时间时计入人工复核。 |

**扩容决策**：若错误集中在多栏、跨页表和手写页，下一轮对照专用 OCR 或版面工具；若文本可靠但检索常漏掉近义问法，再比较两种现有嵌入模型；若证据已召回却答错，再比较现有问答模型。三种问题分别测量，就能判断下一次投入应该用于改善扫描件、调整索引，还是增加模型。
