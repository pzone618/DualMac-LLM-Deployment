# 03｜Mac mini M6 24GB：工作节点部署手册

> **仅在 M6 上执行**，除非明确指出需要 M4 配合。需先读 [`01-总体方案.md`](01-总体方案.md)。
>
> 设备提醒：标准 **M6 Mac mini 只有 Thunderbolt 4 端口**，虽使用雷电 5 线缆连接 M4 Pro，仍以 **TCP over Thunderbolt Bridge** 运行 RPC，不配置 RDMA。

## 0. 收到部署包后先确认目录

将与 M4 相同的压缩包解压，把目录放到：

```text
~/AI/dual-mac-cluster/
```

在 M6 Terminal 验证：

```bash
cd ~/AI/dual-mac-cluster
pwd
ls docs scripts config
uname -m
sw_vers
system_profiler SPHardwareDataType | grep -E 'Model Name|Model Identifier|Chip|Memory'
system_profiler SPThunderboltDataType | head -60
df -h "$HOME"
whoami
```

把 `whoami` 输出记录下来，稍后交给 M4 填写 `M6_USER`。

## 1. 配置 Thunderbolt Bridge

1. 雷电 5 线缆插入 M6 后部 **Thunderbolt 4** 端口；另一头插 M4 Pro 的 Thunderbolt 5 端口。
2. macOS 系统设置 → 网络 → Thunderbolt Bridge；如有必要手动添加网络服务。
3. 手动 IPv4：**10.77.0.2**，子网掩码 **255.255.255.0**，不设置网关/DNS。
4. M4 为 `10.77.0.1/24`。
5. 在 M6 运行：

```bash
ping -c 4 10.77.0.1
route -n get 10.77.0.1
ifconfig | grep -A6 -E '^bridge[0-9]+:'
```

如果 IP 跟你现有局域网/VPN 冲突，双方一起改 IP 与各自 `.env`。

## 2. 启用远程登录 SSH

在 M6：**系统设置 → 通用 → 共享 → Remote Login（远程登录）**，只允许你用于实验的 macOS 用户；按系统提示授权。

接着为该用户创建/编辑 `~/.ssh/authorized_keys`，把从 M4 拿到的公钥**添加为独立一行**（不要覆盖已有 key）：

```bash
mkdir -p ~/.ssh
chmod 700 ~/.ssh
touch ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
nano ~/.ssh/authorized_keys
```

安全提示：只粘贴公钥（通常以 `ssh-ed25519` 开头），**不要复制私钥**。

让 M4 验证：

```bash
ssh <M6用户名>@10.77.0.2 whoami
ssh -o BatchMode=yes <M6用户名>@10.77.0.2 'uname -m'
```

## 3. 配置部署参数

```bash
cd ~/AI/dual-mac-cluster
cp config/cluster.env.example config/cluster.env
nano config/cluster.env
```

保证与 M4 使用相同的网络、模型参数；尤其把 `LLAMA_CPP_REF` 改成 **M4 已编译并记录的完整 SHA**：

```bash
M4_IP=10.77.0.1
M6_IP=10.77.0.2
M6_USER=your_m6_username
LLAMA_CPP_REF=PASTE_FULL_GIT_SHA_HERE
```

**先将 `your_m6_username` 与 `PASTE_FULL_GIT_SHA_HERE` 替换为真实值。不要在 M6 上使用新的 master commit**：RPC 进程和主机程序来自不同源码版本时，协议可能不兼容。

## 4. Homebrew 和 Metal/RPC 编译

先确认 `brew --version` 可用。若尚未安装，请先去 https://brew.sh 安装 Homebrew；不直接从不明镜像执行 install 命令。

```bash
cd ~/AI/dual-mac-cluster
xcode-select -p || xcode-select --install
./scripts/bootstrap.sh
```

它会下载 `llama.cpp` 源码并切换到配置指定 SHA，编译 Metal + RPC，并建立 Python HF CLI 环境。

验证：

```bash
uname -m
git -C ~/AI/llama.cpp rev-parse HEAD
~/AI/llama.cpp/build/bin/ggml-rpc-server --help
~/AI/llama.cpp/build/bin/llama-server --version
```

将 Git SHA 发给 M4，比对其 `git rev-parse HEAD` 输出，必须完全相同。

## 5. 下载 M6 独立推理的测试 GGUF

```bash
cd ~/AI/dual-mac-cluster
./scripts/download-model.sh ggml-org/gemma-3-1b-it-GGUF \
  --file gemma-3-1b-it-Q4_K_M.gguf --source auto
```

需要改为镜像时，可以重跑：

```bash
./scripts/download-model.sh ggml-org/gemma-3-1b-it-GGUF \
  --file gemma-3-1b-it-Q4_K_M.gguf --source mirror
./scripts/download-model.sh verify ggml-org/gemma-3-1b-it-GGUF \
  gemma-3-1b-it-Q4_K_M.gguf
```

`aria2` 的 `.aria2` 和 `.source.json` 文件属于下载状态，不要在中断时删除。也可以从 M4 用 `model-manager.sh download m6` 下载，或者在 M4 先下载、验证后通过 `model-manager.sh sync` 复制到 M6，减少重复连接外网。

GGUF 路径：

```text
~/AI/models/ggml-org__gemma-3-1b-it-GGUF/gemma-3-1b-it-Q4_K_M.gguf
```

分布式模式时，M6 通过 RPC 接收远程张量，**不必**保存分布式大模型的全部 GGUF 副本；独立模式则需要本机 GGUF。参阅 [`04-模型下载与镜像切换.md`](04-模型下载与镜像切换.md)。

## 6. M6 独立模式：前台验证

```bash
cd ~/AI/dual-mac-cluster
./scripts/run-m6-local.sh
```

另开 M6 终端：

```bash
curl -i http://10.77.0.2:8082/health
curl -s http://10.77.0.2:8082/v1/models
```

等待 HTTP 200 和 `status: ok`；测试：

```bash
curl -s http://10.77.0.2:8082/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"messages":[{"role":"user","content":"Hello from M6."}],"max_tokens":64}'
```

成功后 `Ctrl+C` 停掉前台服务。

## 7. M6 RPC Worker：前台验证

```bash
cd ~/AI/dual-mac-cluster
./scripts/run-m6-rpc.sh
```

脚本显式设置：

```bash
GGML_RPC_NO_RDMA=1
```

仅将服务绑定到 `10.77.0.2:50052`。主控 M4 此时可测试：

```bash
nc -G 2 -vz 10.77.0.2 50052
```

此检查仅验证 TCP 端口，不证明最终推理成功。主控需运行带 `--rpc 10.77.0.2:50052` 的 llama-server，并检查日志中识别出的远程设备与模型分配。

成功后按 `Ctrl+C` 停掉前台 Worker，交给集群脚本管理。

## 8. M6 后台模式管理（由 M4 远程调用）

M6 的管理脚本提供：

```bash
cd ~/AI/dual-mac-cluster
./scripts/m6-service.sh local
./scripts/m6-service.sh rpc
./scripts/m6-service.sh status
./scripts/m6-service.sh stop
```

平常不要在 M6 上直接切换，而是在 **M4** 使用：

```bash
cd ~/AI/dual-mac-cluster
./scripts/cluster-mode.sh local
./scripts/cluster-mode.sh distributed
./scripts/cluster-mode.sh status
./scripts/cluster-mode.sh stop
```

原因：主控需同步停止自身的旧模式进程，避免 M4/M6 双方模式不一致。

本包 M6 tmux 会话名：

- `ai-m6-local`：单机 `llama-server`
- `ai-m6-rpc`：RPC Worker

查看运行和日志：

```bash
tmux ls
tail -n 100 ~/AI/logs/m6-local.log
tail -n 100 ~/AI/logs/m6-rpc.log
```

如果 `tmux ls` 显示没有会话，优先检查日志是否因模型路径、端口、动态库或权限问题而退出。

## 9. M6 内存与网络检查

```bash
# 查询某端口是否监听
lsof -nP -iTCP:50052 -sTCP:LISTEN
lsof -nP -iTCP:8082 -sTCP:LISTEN

# 查进程
ps aux | grep -E 'ggml-rpc-server|llama-server' | grep -v grep

# 基础网络
ping -c 4 10.77.0.1
route -n get 10.77.0.1

# 内存压力（M6 终端执行）
vm_stat
```

使用系统 Activity Monitor → Memory 查看内存压力和 swap；对于 24GB 机器尤其重要。分布式模式下如果主控加载小模型，M6 未必承担明显计算负载，**不要把端口打开当成分布式计算验证**。

## 10. 安全与权限

- **仅绑定 Thunderbolt IP**。RPC 服务没有面向不可信网络的安全加固；不要在路由器上做端口转发。
- macOS 防火墙只允许必要的可信专用通信。若 M4 连不上 M6，先查本地网络权限、应用授权和防火墙规则，而不是永久关闭防火墙。
- 如果在 SSH + tmux 后台运行会因 Local Network 权限被系统拒绝，**先在 M6 直接打开 Terminal 前台启动**，确定是后台授权问题，再考虑符合 macOS 规范的 launchd/应用封装。
- 发生 RPC 卡住时，先在 M4 停止分布式客户端，再在 M6 停止 RPC；必要时重启单个工作进程。不要直接下结论是硬件故障。
